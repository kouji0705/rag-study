# この本の書き方

2026年11月10日の改稿方針。公開原稿は `books/cd019af39edb03` にある。`.articles` は構成や出典を置く執筆メモとして扱う。

## 読みたくなる入口を作る

読者に先に見せたいのは、知りたいことへの答えか、身近なつまずき。第1章なら「質問 → マニュアルの一文 → その規定を使った回答例」。第6章なら「答えがあるのに、分からないと返る」という失敗から入る。

各章に要点・前提知識・今回の問い・章内目次をすべて並べる方式はやめる。Zennの目次と重なる案内も削る。途中から読む人のための説明は、その場で必要な用語を一文補い、具体例を出すことで行う。

## 本文の判断基準

- 一つの章で、一つの疑問を解く
- 冒頭の数行に、結論か具体例を置く
- 一つの段落では一つのことだけ説明する
- 同じ内容を段落・表・箇条書きで繰り返さない
- 「この章では何を扱い、何を扱わないか」という予告を重ねない
- 「次章で説明する」は、今の理解に必要な場合か、最後の導線に限る
- 表は比較、図は関係や変化を見せるために使う
- 太字は、流し読みで拾ってほしい結論に絞る
- 未実験の例は「説明用の例」、過去の実行結果は元記事を明示する
- 注記は必要な場所に一度書く。詳細な条件・出典は折りたたみへ置く

短くするために、必要な理由や条件まで消さない。「なぜそうするか」が一文でつながる長さを目指す。文字数のノルマは設けない。

## 図と表

処理図の箱は、まず3〜4個で表せないか考える。箱の名前は短くする。細かなサービス間通信やAPI名は、処理の概要と分ける。

「用意する・検索する・答える」を長い一本の縦図で見せず、質問時の流れと事前準備を分けて説明する。図の中の全文を、直後の段落でもう一度説明しない。

表では、読者が比べたい差を優先する。未計測の指標を埋めた行や、長い出典説明の列を増やさない。結果の条件は表の外へ短く添える。

画像・例示・擬似コードで、未実行の出力や実験結果を作らない。ベクトルなどを説明用の数値で示す場合は、その場で例示と分かるようにする。

## 今回の変更

- 本のタイトルと紹介文に、RAGのどんな疑問に答える本かを明示
- 読む順番を「はじめに → 第1〜7章」に変更。独立した目次・部扉は導入から外し、ファイルは残した
- 第1章は、マニュアルの一文と回答例から開始
- ポケモン記事の経緯や測定値は、RAGの導入から外した
- 第3〜5章は、チャンク・ベクトル・保存データという具体物で説明
- 第6章は、Reranking記事のNaive RAG側の一つの対照実行に絞って説明
- 第7章は、属性条件あり・なしの違いと、絞りすぎる失敗を説明
- 各章の繰り返しの前置き・まとめ・注記を整理
- 未作成の章へのリンクを外し、今ある章だけで読めるように変更
- 本文内の独自の章リンクは使わず、章の移動はZenn標準の目次・前後ナビに統一。現行プレビューでのリンク切れも避ける

原論文と簡易実装の違い、質問セット、コスト計測などの確認事項は、必要になる章で扱う。第1部の導入へすべて前倒ししない。
