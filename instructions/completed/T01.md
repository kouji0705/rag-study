# T01

## 対象

`app/src/corpus.ts` の `hashCorpus`、`indexFingerprint`、`collectionNameFor`、`idDiff`、`upsertBodies`。`app/src/pinned-index.ts` の `indexCorpus`、`verifyIndex`、`openPinnedCollection`。`app/src/commands.ts` の `runIndex`、`runSearch`。`app/src/main.ts` の `verify-index`。`fixtures/manuals/taskflow-v18`。`compose.yaml` の `ARTIFACTS_DIR` と fixtures / artifacts のマウント。

## 実装

資料hashは、相対パスを並べ、改行をLFへ揃えた各ファイルを `path NUL 本文 NUL` で繋いだSHA-256。この18節のhashは `eb0db3cbdb54d6d41943152789885eae94be450b4dcadb0f16985f9042a290bd`。

索引fingerprintは、資料hash、分割版 `heading-v1`、Embedding名の末尾、次元1536、距離 `cosine` から作る。`openai/text-embedding-3-small` と `text-embedding-3-small` は同じ指定として扱う。small と large は別である。コレクション名は `tf` にfingerprint先頭20文字を足したもので、既存の `taskflow` は残る。

`--corpus` 付きの `index` は、全IDと本文が一致したあとにだけ manifest を書く。不一致は終了コード1で、成功manifestは書かない。`verify-index` と、corpus指定の検索は、manifestまたは件数が無いと空の索引を成功にしない。`--corpus` の無い既存コマンドは、これまでどおり `taskflow` を get-or-create する。

## 実験

Chromaを起動した再登録はしていない。run IDは無い。30日と60日のfixtureはhashが変わることだけをテストした。

## 検証

`app/src/pinned-index.test.ts` はHTTPを模して、照合成功、本文不一致、コレクション欠落を確認した。実APIのEmbeddingは呼んでいない。

## 結果

分割そのものは変えていない。IDの規則が変わるとfingerprintの `heading-v1` を上げる必要がある。
